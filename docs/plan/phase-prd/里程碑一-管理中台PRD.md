# 里程碑一 管理中台 PRD

## 1. 文档目的

本文档定义智能教学协同系统 `里程碑一` 阶段管理中台的正式交付范围、页面职责、业务规则与验收标准。

运行环境：新版 Chrome 浏览器中的 Web 管理中台。

## 2. 本阶段交付目标

`里程碑一` 管理中台需要交付一个可独立商用验收的后台治理入口，使管理员能够完成以下工作：

1. 使用管理员账号登录中台。
2. 创建并维护教师账号与学生账号。
3. 维护学校内班级、教室基础数据。
4. 为教师分配班级访问权限和学科权限。
5. 配置教师端模块可见范围与导出权限。
6. 查询基础操作审计记录。

## 3. 本阶段交付范围

1. 管理员登录。
2. 用户管理：教师账号、学生账号。
3. 角色授权：教师、学生、管理员。
4. 学校基础数据：班级、教室。
5. 教师权限配置：可见班级、学科权限、导出权限。
6. 基础模块配置：教师端模块显示开关。
7. 基础审计查询。

## 4. 用户角色与使用边界

| 角色   | 使用入口                   | 允许操作                               |
| ------ | -------------------------- | -------------------------------------- |
| 管理员 | 管理中台 Web 入口          | 用户、班级、教室、权限、基础配置、审计 |
| 教师   | 不使用管理中台进行治理动作 | 无                                     |
| 学生   | 不使用管理中台             | 无                                     |

管理中台只承担治理职责，不承担授课职责，不进入课堂工作流。

## 5. 业务流程

### 5.1 账号与权限初始化流程

1. 管理员登录中台。
2. 创建教师账号。
3. 配置教师所属学科与可见班级。
4. 创建或导入学生账号。
5. 录入班级与教室基础数据。
6. 保存配置并使教师端可用。

### 5.2 教师权限调整流程

1. 管理员进入教师详情页。
2. 修改可见班级、学科权限、导出权限。
3. 保存配置。
4. 系统记录审计日志。
5. 教师下次登录时获取最新权限。

## 6. 模块功能需求

### 6.1 登录模块

管理中台登录页必须包含：

1. 管理员账号输入框。
2. 密码输入框。
3. 登录按钮。
4. 登录状态（包含失败）提示。

登录相关状态通过 toast 展示，登录失败统一提示：`账号与密码组合不存在`。

### 6.2 用户管理模块

本阶段用户管理对象固定为：

1. 教师。
2. 学生。

教师字段固定为：

1. 教师 ID。
2. 姓名。
3. 登录账号。
4. 所属学科。
5. 状态：启用、停用。
6. 可见班级。
7. 导出权限。

学生字段固定为：

1. 学生 ID。
2. 姓名。
3. 学号。
4. 所属班级。
5. 状态：启用、停用。

用户管理必须支持：

1. 新增教师。
2. 编辑教师。
3. 停用教师。
4. 新增学生。
5. 编辑学生。
6. 停用学生。
7. 批量导入学生。

### 6.3 班级与教室模块

班级模块必须支持：

1. 新增班级。
2. 编辑班级。
3. 停用班级。
4. 指定班级教师。

教室模块必须支持：

1. 新增教室。
2. 编辑教室。
3. 维护接收器标识。
4. 绑定默认班级。

班级字段固定为：

1. 班级名称。
2. 年级。
3. 学科。
4. 班主任或任课教师。
5. 状态。

教室字段固定为：

1. 教室名称。
2. 接收器标识。
3. 状态。
4. 默认班级。

### 6.4 权限配置模块

本阶段权限配置必须能管理以下内容：

1. 教师可见班级。
2. 教师可用学科。
3. 教师是否允许导出报表。
4. 教师端模块显示开关：班级管理、设备管理、报表中心、进入课堂。

### 6.5 审计查询模块

`里程碑一` 中台审计覆盖基础操作留痕，必须支持以下查询对象：

1. 用户创建。
2. 用户修改。
3. 用户停用。
4. 班级创建与修改。
5. 教室创建与修改。
6. 教师权限变更。
7. 报表导出权限变更。

审计字段固定为：

1. 日志 ID。
2. 操作人。
3. 角色。
4. 操作对象类型。
5. 操作对象 ID。
6. 操作行为。
7. 操作结果。
8. 时间。
9. 备注。

## 7. 数据留存与查询要求

管理中台必须保存以下数据：

1. 管理员登录日志。
2. 教师账号变更记录。
3. 学生账号变更记录。
4. 班级变更记录。
5. 教室变更记录。
6. 权限变更记录。

查询维度固定为：

1. 操作时间。
2. 操作人。
3. 操作对象类型。
4. 操作结果。

## 8. 异常与失败处理

本阶段管理中台必须显式处理：

1. 登录失败。
2. 权限不足。
3. 账号重复。
4. 班级名称重复。
5. 教室标识重复。
6. 停用对象被教师端占用。
7. 保存失败。
8. 审计查询超时。

失败处理规则固定如下：

1. 表单字段错误必须定位到字段级。
2. 高风险操作必须二次确认：停用教师、停用班级、停用教室。
3. 失败保存不得写入半成功数据。

## 9. 非功能要求

1. 管理中台仅允许管理员访问。
2. 导出内容中的文本字段统一按 UTF-8 编码规范处理。
3. 若设备或操作系统版本过旧，或系统字符集配置异常，不保证所有环境中的展示结果均可完全避免乱码。

## 10. 验收标准

1. 管理员可使用账号密码登录中台。
2. 管理员可创建、编辑、停用教师账号。
3. 管理员可创建、编辑、停用学生账号。
4. 管理员可维护班级和教室基础数据。
5. 管理员可为教师分配班级权限、学科权限和导出权限。
6. 教师重新登录后可获得最新权限。
7. 管理员可查询基础审计记录。

## 11. 依赖与前置条件

1. 后端已提供认证、基础数据、权限、审计接口。
2. 学校已明确首期使用的组织结构、班级、教室与授课教师名单。

## 12. 风险提示

1. 首期不对接客户现有系统，基础数据需人工初始化，准备工作量不可忽略。
2. 权限配置错误会直接影响教师端可见范围和可操作范围。
3. 教室接收器标识若录入错误，会影响设备状态映射与课堂进入验证。
