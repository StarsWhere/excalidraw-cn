# 里程碑一 后端 需求清单

## 1. 文档目的

本文档定义智能教学协同系统 `里程碑一` 阶段后端服务的正式交付范围、领域模型、接口职责、业务规则与验收标准。

运行环境：服务端部署环境，对管理中台 Web 与教师端 Windows 客户端提供接口与实时服务。

## 2. 本阶段交付目标

`里程碑一` 后端需要为教师端和管理中台提供首个可商用课堂闭环所需的统一服务，确保以下业务可稳定运行：

1. 教师与管理员账号认证。
2. 班级、学生、教室基础数据查询与维护。
3. 课次创建、恢复、结束。
4. 设备绑定、在线状态、刷新、解绑、休眠状态同步。
5. 选择题互动任务创建、答案接收、实时统计。
6. 作答情况报表与课次汇总报表生成及 Excel 导出。
7. 初始化配置下发与基础操作审计。

## 3. 本阶段交付范围

1. 认证与令牌服务。
2. 角色权限控制：管理员、教师、学生。
3. 基础数据服务：班级、学生、教室。
4. 课次中心。
5. 设备状态服务。
6. 选择题互动服务。
7. 实时消息通道。
8. 报表生成与 Excel 导出服务。
9. 初始化配置服务。
10. 基础操作日志和导出审计记录。

## 4. 用户角色与使用边界

| 角色   | 消费端       | 允许访问的后端范围                         |
| ------ | ------------ | ------------------------------------------ |
| 管理员 | 管理中台     | 用户授权、基础数据治理、基础配置、审计查询 |
| 教师   | 教师端       | 个人可见班级、学生、教室、课次、互动、报表 |
| 学生   | 设备接入链路 | 仅本人答题提交状态                         |

后端权限控制必须同时满足：

1. 角色权限控制。
2. 数据范围控制。
3. 工作区控制：管理中台接口与教师端接口隔离。

## 5. 业务流程

### 5.1 登录流程

1. 客户端提交账号密码。
2. 后端校验账号状态、密码、角色。
3. 校验通过后生成访问令牌与刷新令牌。
4. 返回用户信息、角色、学科权限、可见班级范围。
5. 记录登录日志。

### 5.2 进入课堂流程

1. 教师端提交班级 ID、教室 ID、学科。
2. 后端校验教师是否有该班级和教室访问权限。
3. 校验当前教师是否已有进行中课次。
4. 校验当前教室是否已有进行中课次。
5. 创建课次记录并返回课次 ID。
6. 推送课次上下文到教师端。

### 5.3 选择题互动流程

1. 教师端创建题目并提交题型、题干、选项、答案、模式、截止时间。
2. 后端创建互动任务记录。
3. 教师端通过本地设备接入能力开始题目并转发设备事件。
4. 后端接收答案事件并校验：课次状态、任务状态、设备绑定、学生身份、作答模式。
5. 后端实时更新统计缓存。
6. 后端通过实时通道推送统计结果到教师端。
7. 教师结束题目后，后端落库最终统计结果。

### 5.4 报表导出流程

1. 教师端按筛选条件请求报表预览。
2. 后端按固定口径查询数据并返回结构化结果。
3. 教师端发起导出请求。
4. 后端生成 Excel 文件并返回下载地址。
5. 记录导出时间、导出人、筛选条件。

## 6. 模块功能需求

### 6.1 认证与账号模块

后端必须提供以下能力：

1. 教师账号密码登录。
2. 管理员账号密码登录。
3. 令牌刷新。
4. 退出登录。
5. 账号状态识别。

返回字段固定包含：

1. 用户 ID。
2. 角色。
3. 用户姓名。
4. 学科权限。
5. 可见班级列表。
6. 访问令牌。
7. 刷新令牌。
8. 令牌过期时间。

失败码必须至少区分：

1. 账号与密码组合不存在。
2. 账号禁用。
3. 无可用角色。

### 6.2 权限控制模块

`里程碑一` 权限矩阵固定如下：

| 角色 | 查看 | 创建/发起 | 编辑/处理 | 删除/结束 | 导出/配置 |
| --- | --- | --- | --- | --- | --- |
| 管理员 | 用户、班级、学生、教室、基础审计 | 用户创建、授权、基础配置 | 用户修改、基础数据修改 | 用户停用 | 配置、审计 |
| 教师 | 本人可见班级、学生、设备、课次、报表 | 课次、题目、导出 | 学生导入、设备解绑、课堂处理 | 结束课次、结束题目 | Excel 导出 |
| 学生 | 本人提交状态 | 提交答案 | 无 | 无 | 无 |

### 6.3 基础数据模块

#### 6.3.1 班级

班级字段固定为：

1. 班级 ID。
2. 班级名称。
3. 年级。
4. 学科。
5. 教师 ID。
6. 教室 ID。
7. 状态。

#### 6.3.2 学生

学生字段固定为：

1. 学生 ID。
2. 学生姓名。
3. 学号。
4. 班级 ID。
5. 座号。
6. 设备编号。
7. 状态。

#### 6.3.3 教室

教室字段固定为：

1. 教室 ID。
2. 教室名称。
3. 接收器标识。
4. 网络状态。
5. 当前课次状态。

基础数据模块必须支持：

1. 教师账号查询、新增、编辑、停用。
2. 班级查询、新增、编辑、停用、指定教师。
3. 学生新增、编辑、停用、导入、查询。
4. 教室查询、新增、编辑、维护接收器标识、绑定默认班级。
5. 教师可见范围校验。

### 6.4 课次中心

课次是 `里程碑一` 所有课堂数据的主线实体。

课次字段固定为：

1. 课次 ID。
2. 班级 ID。
3. 教师 ID。
4. 教室 ID。
5. 学科。
6. 开始时间。
7. 结束时间。
8. 状态：待开始、进行中、中断、已结束。

业务规则固定如下：

1. 同一教师同一时刻仅允许一个进行中课次。
2. 同一教室同一时刻仅允许一个进行中课次。
3. 课次结束后不得继续新增互动题目。
4. 中断课次允许恢复。

### 6.5 设备状态模块

本阶段设备集成边界如下：

1. 后端与设备接入实现解耦，不直接依赖教师端的具体底层组件形态。
2. 教师端负责完成设备会话控制、开题、结束题目、回显设置和休眠动作，具体实现方式由技术方案决定。
3. 教师端需将设备连接、设备断开、按键作答、设备状态、电量、信号、休眠结果等标准化事件同步到后端。
4. 后端只接收标准化后的业务事件和状态数据，不要求感知客户端内部封装细节。

设备状态字段固定为：

1. 设备编号。
2. 学生 ID。
3. 连接状态。
4. 心跳时间。
5. 电量。
6. 信号强度。
7. 固件版本。
8. 绑定状态。

设备服务必须支持以下动作：

1. 查询设备列表。
2. 刷新设备状态。
3. 设备解绑。
4. 设备休眠。
5. 课堂前状态确认。

掉线判断规则固定为：

1. 最近心跳超过配置阈值即视为离线。
2. 离线设备仍保留绑定关系，不自动解绑。

### 6.6 选择题互动模块

本阶段支持题型：

1. 判断题。
2. 单选题。
3. 多选题。

本阶段支持模式：

1. 全班作答。
2. 抢答。
3. 指定学生作答。

互动任务字段固定为：

1. 任务 ID。
2. 课次 ID。
3. 题型。
4. 题干。
5. 选项。
6. 正确答案。
7. 作答模式。
8. 开始时间。
9. 截止时间。
10. 是否允许修改答案。
11. 状态：待开始、进行中、已截止、已结束。

答案记录字段固定为：

1. 任务 ID。
2. 学生 ID。
3. 设备编号。
4. 提交答案。
5. 提交时间。
6. 提交次数。
7. 是否有效答案。

统计结果字段固定为：

1. 应到人数。
2. 实答人数。
3. 参与率。
4. 正确人数。
5. 正确率（按应到）。
6. 正确率（按实答）。
7. 未作答人数。
8. 缺席人数。
9. 选项分布。
10. 抢答顺序。

业务规则固定如下：

1. 多选题按全对计分。
2. 抢答模式以服务端收到的第一条有效提交为准。
3. 指定学生作答模式下，非指定学生答案一律拒绝。
4. 若不允许修改答案，则保留第一条有效提交。
5. 若允许修改答案，则截止前最后一条有效提交为准。

### 6.7 实时消息通道

实时消息通道职责固定为：

1. 推送设备状态变更。
2. 推送题目状态变更。
3. 推送统计结果。
4. 推送课次状态变更。

### 6.8 报表与导出模块

报表类型固定为：

1. 作答情况报表。
2. 课次汇总报表。

导出格式固定为：

`Excel`

导出命名固定为：

`{班级名称}_{课次日期}_{报表类型}.xlsx`

导出筛选维度固定为：

1. 班级。
2. 课次日期。
3. 课次。
4. 报表类型。

### 6.9 初始化配置下发模块

本阶段后端必须向教师端下发以下初始化配置：

1. 设备离线判定阈值。
2. 可见模块列表。
3. 可见学科能力列表。
4. 导出命名规则。

## 7. 数据留存与查询要求

`里程碑一` 后端必须留存以下数据：

1. 登录日志。
2. 用户权限范围。
3. 班级、学生、教室主数据。
4. 课次记录。
5. 设备状态快照。
6. 互动任务。
7. 学生答案记录。
8. 报表导出记录。

查询维度固定为：

1. 按课次。
2. 按班级。
3. 按教师。
4. 按日期范围。

## 8. 异常与失败处理

本阶段后端必须显式处理：

1. 登录失败。
2. 权限不足。
3. 班级或教室不存在。
4. 课次冲突。
5. 设备未连接。
6. 设备绑定冲突。
7. 题目已截止。
8. 重复提交冲突。
9. 实时消息通道断连。
10. 报表导出失败。

失败处理规则固定如下：

1. 所有失败接口必须返回可区分错误码。
2. 实时统计失败时不得丢失已落库答案。
3. 导出失败需保留失败记录。
4. 课次中断时保留当前上下文，允许恢复。

## 9. 非功能要求

1. 单课次支持不少于 20 名学生在线参与选择题互动。

## 10. 验收标准

1. 教师与管理员账号可正常登录。
2. 教师仅可访问本人可见班级、学生、课次和报表。
3. 教师可创建、恢复、结束课次。
4. 设备状态可同步到后端并在教师端显示。
5. 判断题、单选题、多选题、抢答题可完成创建、接收、统计、结束全流程。
6. 实时统计结果与最终落库结果一致。
7. 作答情况报表和课次汇总报表可预览并导出 Excel。
8. 导出行为和登录行为可被审计查询。

## 11. 依赖与前置条件

1. 教师端本地需具备首期接入设备的连接、控制与事件采集能力。
2. 管理中台已具备基础数据录入与账号授权能力。
3. 云端部署环境具备数据库、文件存储和实时通道支持。

## 12. 风险提示

1. 设备事件由教师端本地转发，若教师端与云端网络中断，会影响实时统计。
2. 设备心跳与状态同步依赖设备接入能力稳定性。
3. 若学校网络质量不稳定，抢答顺序可能受到链路延迟影响，需以服务端时间为唯一判定依据。
