# 里程碑一 管理中台 需求清单

## 1. 文档目的

本文档定义智能教学协同系统 `里程碑一` 阶段管理中台的正式交付范围、页面职责、业务规则与验收标准。

运行环境：新版 Chrome 浏览器中的 Web 管理中台。

## 2. 本阶段交付目标

`里程碑一` 管理中台需要交付一个可独立商用验收的后台治理入口，面向平台运营者（管理员）完成以下工作：

1. 使用管理员账号登录中台。
2. 创建并维护教师账号，并维护学校级学生、班级、教室基础数据。
3. 为班级配置一位或多位任课教师，并为教师分配可见班级、学科权限、模块权限与导出权限。
4. 配置同校范围内教室查看与使用规则。
5. 维护教室接收器标识、归档与恢复等高风险治理动作。
6. 查询管理中台与教师端统一审计记录。

## 3. 本阶段交付范围

1. 管理员登录。
2. 用户管理：教师账号、学生账号。
3. 角色授权：教师、学生、管理员。
4. 学校基础数据：班级、教室、班级与教师关系、班级与教室关系。
5. 教师权限配置：可见班级、学科权限、导出权限、模块显示开关。
6. 教室治理配置：接收器标识、归档恢复、同校教室使用规则。
7. 统一审计查询。

## 4. 用户角色与使用边界

| 角色 | 使用入口 | 允许操作 |
| --- | --- | --- |
| 平台运营者（管理员） | 管理中台 Web 入口 | 用户治理、班级治理、教室治理、权限配置、基础配置、审计查询 |
| 教师 | 不通过管理中台进行治理动作 | 无 |
| 学生 | 不使用管理中台 | 无 |

管理中台只承担平台治理职责，不承担授课职责，不进入课堂工作流。教师可在教师端管理工作区维护授权范围内的教学准备数据，但不通过管理中台执行治理动作。

## 5. 业务流程

### 5.1 账号与权限初始化流程

1. 平台运营者登录中台。
2. 创建教师账号，并配置所属学校、可用学科、可见班级、导出权限和模块显示开关。
3. 录入学校级班级、教室基础数据，并配置班级与教师、班级与教室关系。
4. 维护教室接收器标识与同校教室查看使用规则。
5. 按需创建或导入学生账号。
6. 保存配置并使教师端可用。

### 5.2 教师权限调整流程

1. 平台运营者进入教师详情页。
2. 修改可见班级、学科权限、导出权限、模块显示开关与同校教室规则。
3. 保存配置。
4. 系统记录审计日志。
5. 教师下次登录时获取最新权限。
6. 若教师正在进行课堂，当前课次不被立即打断；课次结束后按最新权限生效。

## 6. 模块功能需求

### 6.1 登录模块

管理中台登录页必须包含：

1. 管理员账号输入框。
2. 密码输入框。
3. 登录按钮。
4. 登录状态（包含失败）提示。

登录相关状态通过 toast 展示，登录失败统一提示：`账号与密码组合不存在`。

### 6.2 用户管理模块

本阶段用户管理对象固定为：

1. 教师。
2. 学生。

教师账号字段固定为：

1. 教师 ID。
2. 登录账号。
3. 所属学校。
4. 状态：启用、停用。
5. 可见班级。
6. 可用学科。
7. 导出权限。
8. 模块权限。

教师资料展示字段固定为：

1. 姓名展示。
2. 联系方式。

学生字段固定为：

1. 学生 ID。
2. 姓名。
3. 学号。
4. 所属学校。
5. 所属班级。
6. 状态：启用、停用。
7. 性别。
8. 座号。
9. 设备编号。

用户管理必须支持：

1. 新增教师。
2. 编辑教师。
3. 停用教师。
4. 新增学生。
5. 编辑学生。
6. 停用学生。
7. 批量导入学生。
8. 查看教师端创建或导入的正式学生账号。

学生导入规则固定如下：

1. 管理中台与教师端共用同一套 `CSV` 模板。
2. 必填字段：学生姓名、学号、所属班级。
3. 可选字段：性别、座号、设备编号。
4. 同一学校内学号不得重复。
5. 导入结果按批次记录总行数、成功数、失败数，逐行失败原因保留在导入详情中。

### 6.3 班级与教室模块

班级模块必须支持：

1. 新增班级。
2. 编辑班级。
3. 停用班级。
4. 为同一班级指定一位或多位教师。
5. 维护班级与教室关联关系。
6. 查看班级当前可见教师范围。

教室模块必须支持：

1. 新增教室。
2. 编辑教室。
3. 维护接收器标识。
4. 维护教室关联班级列表。
5. 查看教室关联教师状态与占用状态。
6. 归档教室。
7. 恢复教室。

班级字段固定为：

1. 班级名称。
2. 年级。
3. 所属学校。
4. 任课教师列表。
5. 关联教室列表。
6. 状态：启用、停用。

教室字段固定为：

1. 教室名称。
2. 接收器标识。
3. 所属学校。
4. 关联班级列表。
5. 关联教师状态。
6. 占用状态。
7. 状态：启用、归档。

基础数据规则固定如下：

1. 班级名称在同校同年级范围内不得重复。
2. 教室名称在同校范围内不得重复。
3. 接收器标识全局唯一。
4. 教师端与管理中台共享同一套后端主数据，后写覆盖，统一审计。
5. 教师仅看得到运营者授权给自己的班级，以及自己创建或被关联后新增可见的班级。

### 6.4 权限配置模块

本阶段权限配置必须能管理以下内容：

1. 教师可见班级。
2. 教师可用学科。
3. 教师是否允许导出报表。
4. 教师端模块显示开关：班级与学生初始化、教室管理、设备管理、报表中心、进入课堂。
5. 同校范围内教室查看与使用规则。

权限规则固定如下：

1. 教师端模块入口是否显示由模块开关决定。
2. 模块显示后，具体操作仍需校验教师的班级、导出和学科权限。
3. 权限、模块开关、导出权限统一在教师下次登录时生效。
4. 教师在当前课次中被停用时，当前课次允许继续，结束后不可再次登录或进入课堂。

### 6.5 审计查询模块

`里程碑一` 中台审计覆盖管理中台与教师端关键操作留痕，必须支持以下查询对象：

1. 用户创建、修改、停用。
2. 班级创建、修改、停用。
3. 教室创建、修改、归档、恢复。
4. 班级与教师关系变更。
5. 班级与教室关系变更。
6. 教师权限变更。
7. 报表导出权限变更。
8. 教师端学生创建、编辑、调班、导入批次。
9. 教师端进入课堂、结束课堂。
10. 教师端报表导出成功、失败、拒绝。
11. 教师端失败操作与权限拒绝事件。

审计字段固定为：

1. 日志 ID。
2. 操作人。
3. 角色。
4. 来源系统/入口。
5. 操作对象类型。
6. 操作对象 ID。
7. 操作行为。
8. 操作结果。
9. 时间。
10. 备注。

## 7. 数据留存与查询要求

管理中台必须保存以下数据：

1. 管理员登录日志。
2. 教师账号变更记录。
3. 学生账号变更记录。
4. 班级变更记录。
5. 教室变更记录。
6. 班级与教师关系变更记录。
7. 班级与教室关系变更记录。
8. 教室归档与恢复记录。
9. 权限变更记录。
10. 教师端关键业务操作记录。
11. 教师端失败与拒绝操作记录。

查询维度固定为：

1. 操作时间。
2. 操作人。
3. 来源系统/入口。
4. 操作对象类型。
5. 操作结果。

共享数据同步规则固定如下：

1. 不要求跨端实时推送。
2. 另一端在下次进入列表页、详情页或重新加载时必须拉取最新数据。
3. 审计记录必须保留成功、失败、拒绝三类结果。

## 8. 异常与失败处理

本阶段管理中台必须显式处理：

1. 登录失败。
2. 权限不足。
3. 账号重复。
4. 学生学号重复。
5. 班级名称重复。
6. 教室名称重复。
7. 教室标识重复。
8. 停用对象被教师端占用。
9. 保存失败。
10. 审计查询超时。
11. 教室归档或恢复条件不满足。

失败处理规则固定如下：

1. 表单字段错误必须定位到字段级。
2. 高风险操作必须二次确认：停用教师、停用学生、停用班级、归档教室、恢复教室、解除他人任课关系。
3. 失败保存不得写入半成功数据。
4. 权限拒绝和失败操作必须写入审计记录。

## 9. 非功能要求

1. 管理中台仅允许管理员访问。
2. 所有导出内容中的文本字段统一按 UTF-8 编码规范处理。
3. 若设备或操作系统版本过旧，或系统字符集配置异常，不保证所有环境中的展示结果均可完全避免乱码。
4. 管理中台视觉风格采用明亮、轻快、教育场景友好的浅色主题，不使用过于艳丽或过于深沉的主色调。

## 10. 验收标准

1. 平台运营者可使用账号密码登录中台。
2. 平台运营者可创建、编辑、停用教师账号。
3. 平台运营者可创建、编辑、停用学生账号，并查看教师端创建或导入的正式学生账号。
4. 平台运营者可维护班级和教室基础数据、接收器标识及教室规则。
5. 平台运营者可为同一班级配置一位或多位教师，并维护班级与教室关联关系。
6. 平台运营者可为教师分配班级权限、学科权限、导出权限和模块权限。
7. 平台运营者可查看教室关联班级列表、关联教师状态、占用状态，并按规则归档或恢复教室。
8. 教师重新登录后可获得最新权限；教师课堂中被停用时，当前课次可继续，结束后权限失效。
9. 平台运营者可查询管理中台与教师端统一审计记录。

## 11. UI 交付说明

1. 对于有定制风格、特殊布局或关键交互要求的页面，需提供对应的 UI 线稿、原型或页面示意作为实现依据。
2. 当前未提供完整 UI 线稿或示意的页面，默认按教育行业通用规范、常规交互方式和项目既有风格进行设计与实现。
3. 颜色、字号、字重、间距等简单样式调整可在开发过程中配合修改。
4. 涉及页面结构、布局、信息层级或交互逻辑的调整，视为需求变更，需重新评估范围、排期与成本。

## 12. 依赖与前置条件

1. 后端已提供认证、基础数据、权限、审计接口。
2. 学校已明确首期使用的组织结构、班级、教室与授课教师名单。
3. 教师端与管理中台共享同一套主数据与审计底座。
