# 里程碑一 管理中台 需求清单

## 1. 文档目的

本文档定义智能教学协同系统 `里程碑一` 阶段管理中台的正式交付范围、页面职责、业务规则与验收标准。

运行环境：新版 Chrome 浏览器中的 Web 管理中台。

管理中台仅面向平台管理者使用，不作为教师或学校管理员的使用入口。

## 2. 本阶段交付目标

`里程碑一` 管理中台需交付一个可独立商用验收的跨校治理入口，完成以下工作：

1. 平台管理者登录管理中台。
2. 平台管理者开通学校并维护学校级基础配置。
3. 平台管理者创建、编辑、停用学校管理员账号。
4. 平台管理者具备跨校全量查看与管理能力，并保留最终覆盖权。
5. 平台管理者查询跨端统一审计记录。

学校内日常教学治理以学校管理员为主责；平台管理者保留跨校治理与覆盖能力。

## 3. 本阶段交付范围

### 3.1 核心功能

1. 平台管理者登录。
2. 学校开通与学校管理员账号治理。
3. 跨校范围用户与基础数据治理。
4. 跨校权限治理。
5. 统一审计查询。

### 3.2 非核心功能

1. 统一审计高级筛选能力。

## 4. 用户角色与使用边界

### 4.1 角色定义

| 角色 | 使用入口 | 核心职责 | 不可用能力 |
| --- | --- | --- | --- |
| 平台管理者 | 管理中台 Web 入口 | 跨校治理、学校开通、学校管理员账号治理、跨校审计、跨校覆盖管理 | 不通过教师端授课 |
| 学校管理员 | 教师端客户端（管理端/课堂端） | 学校日常治理主责：普通教师账号管理、班级管理、学生名单管理、授课关系管理、普通教师权限分配、设备正式绑定维护；也可授课 | 不通过管理中台执行平台治理；不能创建或停用学校管理员账号 |
| 教师 | 教师端客户端（管理端/课堂端） | 教学准备、设备检查、进入课堂、发起互动、导出授权报表 | 不可维护学生名单；不可维护授课关系；不可管理普通教师账号；不通过管理中台治理 |
| 学生 | 不直接使用教师端和管理中台 | 无 | 不进入管理入口 |

学校管理员是教师体系中的高权限角色。学校内日常治理由学校管理员主责，平台管理者保留跨校最终覆盖权。

### 4.2 入口边界

1. 管理中台仅允许平台管理者访问。
2. 教师端管理端由学校管理员与教师共用同一页面，按权限显示模块与操作。
3. 教师端课堂端由学校管理员与教师使用，完成授课与互动。
4. 角色越权访问必须被拒绝并提示原因。

## 5. 业务流程

### 5.1 平台治理流程

1. 平台管理者登录管理中台。
2. 开通学校并维护学校基础配置。
3. 创建、编辑、停用学校管理员账号。
4. 维护跨校策略与平台权限控制项。
5. 保存配置并写入统一审计。

### 5.2 跨校覆盖流程

1. 平台管理者按学校维度检索目标数据。
2. 执行跨校查看或跨校修改。
3. 系统记录操作前后差异与操作原因。
4. 审计日志可按角色、学校、对象、结果追溯。

## 6. 模块功能需求

### 6.1 登录模块

管理中台登录页必须包含：

1. 平台管理者账号输入框。
2. 密码输入框。
3. 登录按钮。
4. 登录状态提示。

登录失败统一提示：`账号与密码组合不存在`。

### 6.2 学校与账号治理模块

本阶段必须支持：

1. 开通学校。
2. 编辑学校状态与基础配置。
3. 创建、编辑、停用学校管理员账号。
4. 查看学校内角色与权限分布概览。

固定规则：

1. 学校管理员账号仅由平台管理者管理。
2. 平台管理者可跨校检索与管理学校级数据。
3. 跨校修改必须写入操作原因与审计记录。

### 6.3 跨校治理模块

本阶段必须支持：

1. 跨校用户治理。
2. 跨校班级治理。
3. 跨校学生治理。
4. 跨校授课关系治理。
5. 跨校设备治理。

固定规则：

1. 平台管理者具备跨校全量管理能力。
2. 学校内日常治理由学校管理员主责。
3. 平台管理者保留最终覆盖权。

### 6.4 审计查询模块

中台审计覆盖管理中台与教师端关键操作，支持以下对象：

1. 账号创建、编辑、停用、重置。
2. 班级创建、编辑、停用。
3. 学生创建、编辑、调班、导入。
4. 授课关系变更。
5. 权限变更。
6. 设备正式绑定变更。
7. 设备自动分配与回收结果。
8. 进入课堂与结束课堂。
9. 报表导出成功、失败、拒绝。
10. 角色越权访问拒绝事件。

审计字段固定为：

1. 日志 ID。
2. 操作人。
3. 角色。
4. 来源系统/入口。
5. 操作对象类型。
6. 操作对象 ID。
7. 操作行为。
8. 操作结果。
9. 时间。
10. 备注。

## 7. 数据留存与查询要求

管理中台必须保存以下数据：

1. 平台管理者登录日志。
2. 学校开通与状态变更记录。
3. 学校管理员账号变更记录。
4. 跨校用户变更记录。
5. 跨校班级变更记录。
6. 跨校学生变更记录。
7. 跨校授课关系变更记录。
8. 跨校设备变更记录。
9. 权限变更记录。
10. 教师端关键业务操作记录。
11. 失败与拒绝操作记录。

查询维度固定为：

1. 操作时间。
2. 操作人。
3. 角色。
4. 来源系统/入口。
5. 操作对象类型。
6. 操作结果。

## 8. 异常与失败处理

本阶段管理中台必须显式处理：

1. 登录失败。
2. 权限不足。
3. 学校标识重复或冲突。
4. 学校管理员账号重复。
5. 跨校对象不存在或状态冲突。
6. 保存失败。
7. 审计查询超时。

失败处理规则：

1. 表单字段错误定位到字段级。
2. 高风险操作需二次确认：停用学校管理员账号、跨校覆盖修改、跨校停用关键对象。
3. 失败保存不得写入半成功数据。
4. 权限拒绝与失败操作必须写入审计。

## 9. 非功能要求

1. 管理中台仅允许平台管理者访问。
2. 所有导出内容文本字段统一按 UTF-8 编码处理。
3. 若设备或系统版本过旧，不保证所有环境均完全避免乱码。
4. 视觉风格采用明亮、轻快、教育场景友好的浅色主题。

## 10. 验收标准

1. 平台管理者可登录管理中台并完成学校开通。
2. 平台管理者可创建、编辑、停用学校管理员账号。
3. 平台管理者具备跨校全量查看与管理能力。
4. 平台管理者执行跨校覆盖操作时可完整追溯审计。
5. 管理中台可查询管理中台与教师端统一审计记录。

## 11. UI 交付说明

1. 有定制风格、特殊布局或关键交互要求的页面需提供线稿或原型。
2. 未提供完整线稿页面默认按教育行业通用规范和项目既有风格实现。
3. 颜色、字号、字重、间距等简单样式可在开发过程中配合调整。
4. 页面结构、信息层级、交互逻辑调整视为需求变更，需重新评估范围与排期。

## 12. 依赖与前置条件

1. 后端已提供认证、主数据、权限、审计接口。
2. 学校已明确班级结构、授课教师名单、设备清单。
3. 管理中台与教师端共享同一套主数据与审计底座。
